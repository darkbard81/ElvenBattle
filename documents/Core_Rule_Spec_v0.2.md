# Core Rule Spec v0.2 — TCG 기본 규칙 초안

작성일: 2026-06-10

전면 수정일: 2026-06-12

수정 목적: 기존 전역 지배력/자원 중심 설명을 폐기하고, **리더가 만든 지배력 위에 카드를 전개하는 보드 중심 TCG 규칙**을 최상위 기준으로 재정의한다.

## 최우선 기준

이 문서는 ElvenBattle의 Phase15 이후 v0.2 전환 목표 룰 기준이다. Phase3~14 구현 추적과 회귀 비교는 `Core_Rule_Spec_v0.1.md`를 기준으로 보존한다. v0.2 구현, Phase15 이후 문서, 테스트, 카드 데이터가 이 문서와 충돌하면 이 문서를 우선한다.

원작 보호 대상 카드 데이터, 명칭, 일러스트, 스토리, 고유 리소스는 복제하지 않는다. 창각의 아테리얼은 보드 배치, 리더, 코스트, 지배력의 구조적 감각만 참고한다.

## 1. 게임 목표

상대 리더의 체력을 0으로 만들면 승리한다.

```text
승리 조건:
  상대 리더 체력 <= 0
```

동시에 양쪽 리더 체력이 0 이하가 되면 별도 무승부/우선순위 규칙이 필요하다. MVP에서는 동시 패배를 무승부로 처리한다.

## 2. 게임 구성

```text
덱:
  플레이어가 전투에 사용하는 카드 묶음.

핸드:
  플레이어가 현재 사용할 수 있는 손패.

보드:
  카드를 배치하고 전투가 진행되는 칸들의 집합.
  각 칸에는 카드가 놓일 수 있다.
  카드의 위치에 따라 지배력이 주변 칸에 퍼진다.

리더:
  플레이어를 대표하는 핵심 카드.
  리더가 쓰러지면 패배한다.
  초기 보드에 배치되어 초반 전개의 기준 지배력을 만든다.
```

## 3. 초기 준비

```text
덱:
  각 플레이어는 30장 덱을 사용한다.

초기 핸드:
  각 플레이어는 덱에서 6장을 뽑고 시작한다.

초기 보드:
  각 플레이어는 자신의 리더를 시작 위치에 배치한다.

선공:
  선공 플레이어부터 턴을 진행한다.
```

MVP 구현에서 리더가 아직 별도 카드 인스턴스로 표현되지 않았다면, 리더 체력과 리더 지배력은 `PlayerState` 또는 시나리오 초기 상태로 표현할 수 있다. 단, 최종 룰 모델은 리더가 보드 위 위치를 가진다는 점을 기준으로 한다.

## 4. 카드 코스트와 지배력

```text
코스트:
  카드를 보드에 배치하기 위해 필요한 수치.
  카드의 강함과 등장 시점을 조절한다.

지배력:
  카드가 주변 칸에 제공하는 배치 가능 수치.
  보드 위 위치 전략과 전개 속도를 만든다.

배치 조건:
  카드 코스트 <= 해당 칸에 모인 지배력 합
```

예시:

```text
해당 칸의 지배력 합이 1:
  코스트 0~1 카드 배치 가능

해당 칸의 지배력 합이 3:
  코스트 0~3 카드 배치 가능
```

지배력은 소비하지 않는다. 지배력은 보드 위 카드들의 위치와 제공값에서 계산되는 배치 가능 수치다.

## 5. 카드 배치

플레이어는 자신의 턴에 핸드의 카드를 보드 위 빈 칸에 배치할 수 있다.

```text
배치 가능 조건:
  1. 빈 칸이어야 한다.
  2. 해당 칸에 지배력이 있어야 한다.
  3. 카드 코스트가 해당 칸의 지배력 합 이하이어야 한다.
  4. 카드별 배치 제한이 있으면 그 제한을 만족해야 한다.
```

카드가 배치되면 그 카드의 지배력이 주변 칸에 적용된다.

배치 실패 예:

```text
빈 칸이 아님:
  배치 불가

해당 칸 지배력 합 0:
  배치 불가

해당 칸 지배력 합 1, 카드 코스트 2:
  배치 불가
```

## 6. 턴 진행

각 턴은 다음 순서로 진행한다.

```text
1. 드로우 단계
   덱에서 카드 1장을 뽑는다.

2. 배치 단계
   조건을 만족하는 카드를 보드에 배치할 수 있다.

3. 행동 단계
   자신의 카드를 이동, 공격, 효과 사용 중 하나로 행동시킬 수 있다.

4. 종료 단계
   턴을 종료하고 상대에게 차례를 넘긴다.
```

MVP 구현에서 기존 `MAIN`, `COMBAT`, `END` 페이즈를 사용하더라도 의미는 위 순서에 맞춘다.

## 7. 전투

카드는 공격 범위 안의 상대 카드를 공격할 수 있다. 기본 공격 범위는 인접 칸이다.

```text
공격 조건:
  1. 공격 가능한 상태여야 한다.
  2. 대상이 공격 범위 안에 있어야 한다.
  3. 이미 행동한 카드는 다시 공격할 수 없다.
```

전투 시 공격력만큼 대상에게 피해를 준다.

```text
피해 처리:
  대상 체력 -= 공격 카드의 공격력

파괴 조건:
  대상 체력 <= 0
```

파괴된 카드는 보드에서 제거되고 묘지 또는 별도 제거 영역으로 이동한다.

## 8. 리더 공격

상대 리더가 공격 범위 안에 있으면 리더를 직접 공격할 수 있다.

```text
리더 피해:
  상대 리더 체력 -= 공격 카드의 공격력

패배 조건:
  리더 체력 <= 0
```

리더는 게임의 중심 목표다. 보드 위 리더 위치, 리더 주변 지배력, 리더 공격 가능 조건은 전투와 배치 전략의 핵심이 된다.

## 9. 카드 효과

일부 카드는 고유 효과를 가진다.

```text
상시 효과:
  카드가 보드에 있는 동안 계속 적용된다.

등장 효과:
  카드가 배치되었을 때 1회 발동한다.

행동 효과:
  자신의 행동 단계에 사용한다.

파괴 효과:
  카드가 파괴될 때 발동한다.
```

효과와 기본 규칙이 충돌할 경우, 카드 효과를 우선한다.

단, 카드 효과도 다음 원칙을 깨지 않는다.

```text
리더 체력 <= 0이면 패배한다.
덱, 핸드, 보드, 묘지 등 카드 위치는 항상 추적 가능해야 한다.
무작위 처리는 seed 기반으로 재현 가능해야 한다.
```

## 10. 기본 설계 원칙

```text
핸드:
  선택지를 제공한다.

보드:
  위치 전략을 만든다.

지배력:
  전개 속도와 배치 범위를 제한한다.

코스트:
  카드의 강함과 등장 시점을 조절한다.

리더:
  게임의 중심 목표가 된다.
```

## 11. 초반 배치 기준

초반의 일반적인 리더는 주변 칸에 지배력 1을 제공한다.

따라서 최초로 보드에 배치할 수 있는 기본 카드는 코스트 1 이하이다.

```text
초기 리더 지배력:
  주변 칸에 지배력 1 제공

최초 배치 가능 카드:
  코스트 0~1 카드

기본 기준:
  첫 전개 카드는 코스트 1 이하로 설계한다.
```

## 12. 핵심 요약

```text
카드를 배치한다.
배치한 카드가 지배력을 만든다.
지배력으로 더 강한 카드를 전개한다.
보드에서 전투한다.
상대 리더를 쓰러뜨리면 승리한다.
```

## 13. 구현 지침

### 13.1 룰 엔진

- 룰 엔진은 UI, DOM, Phaser, 네트워크에 의존하지 않는다.
- 모든 상태 변화는 action 처리 함수로만 일어난다.
- 배치, 이동, 공격, 효과 사용은 검증과 적용을 분리한다.
- 결정론이 필요한 로직은 `Math.random()`과 현재 시간에 직접 의존하지 않는다.

### 13.2 데이터 모델

카드 정의에는 최소한 다음 값이 필요하다.

```text
cardId
type
cost
dominanceValue
attack
health
placementRestriction
abilities
rarity
```

리더 정의에는 최소한 다음 값이 필요하다.

```text
leaderId
health
startingSlot
dominanceValue
attackRange
abilities
```

### 13.3 보드와 지배력 계산

보드는 칸들의 집합이다. 각 칸의 지배력 합은 다음 값의 합이다.

```text
slotDominance =
  해당 칸에 영향을 주는 내 리더의 dominanceValue
  + 해당 칸에 영향을 주는 내 카드들의 dominanceValue
  + 카드 효과나 시나리오가 추가한 지배력
```

기본 전파 범위는 주변 칸이다. 정확한 주변 칸 정의는 보드 형태에 따라 정한다. 현재 2행 x 3열 MVP에서는 같은 플레이어 보드의 인접 칸을 우선 사용한다.

### 13.4 현재 구현과의 차이

현재 코드 일부는 과거 전역 지배력 한계, 일반 자원, 전열/후열 전투 규칙을 포함한다. 이후 구현은 다음 방향으로 정리한다.

```text
전역 지배력 한계:
  제거 또는 UI 표시용 보조값으로 축소

일반 자원:
  카드 사용 비용으로 남길 수 있으나, 보드 배치의 핵심 조건은 지배력 합과 카드 코스트

리더:
  Player HP가 아니라 보드 위 리더 카드/유닛으로 모델링

공격:
  같은 열 우선 규칙보다 인접 공격 규칙을 우선 검토
```

## 14. 범위 밖

다음은 현재 핵심 규칙 문서의 범위 밖이다.

- 원작 카드 데이터 복제
- 원작 캐릭터/스토리/이미지 사용
- PvP 네트워크 동기화
- 계정, 결제, 클라우드 저장
- 장기 성장/보상 시스템
- 복잡한 카드 제작 경제

## 15. 다음 구현 우선순위

1. 리더를 보드 위 객체로 모델링한다.
2. 초기 보드에 리더를 배치한다.
3. 리더 주변 칸에 지배력 1이 적용되도록 계산한다.
4. 카드 배치 조건을 `card.cost <= slotDominance`로 고정한다.
5. 시작 손패 6장, 덱 30장 기준을 유지한다.
6. 공격 범위를 인접 칸 기준으로 재검토한다.
7. 상대 리더 체력 0 이하 승리 조건을 최우선 종료 조건으로 둔다.
