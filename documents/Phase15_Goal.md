# Phase 15 목표 지시문 — v0.2 리더 / 칸별 지배력 / 인접 전투 전환

너는 Node.js + TypeScript + Vite + Phaser 기반 디지털 TCG 게임 엔진을 v0.1 구현 기준에서 v0.2 룰 기준으로 전환하는 엔지니어다.

아래 문서를 기준으로 Phase 15를 완성하기 위한 구체적인 구현 목표, 영향 범위, 테스트 조건을 정의한다.

## 기준 문서

- `documents/Plan.md`
- `documents/Core_Rule_Spec_v0.1.md`
- `documents/Core_Rule_Spec_v0.2.md`
- `documents/Phase14_Goal.md`
- `AGENTS.md`

## Phase 15의 위치

`documents/Plan.md`에서 Phase 15는 다음 단계다.

- Phase 13: Phaser UI 및 PvE 콘텐츠 구현
- Phase 14: 테스트 / 밸런스 / 배포
- Phase 15: v0.2 리더 / 칸별 지배력 / 인접 전투 전환

Phase 15는 프로젝트를 새로 만들지 않고 기존 엔진을 유지한 채 룰 중심축을 전환하는 단계다. Phase3~14 구현과 검증은 `Core_Rule_Spec_v0.1.md` 기준으로 추적하고, 새 전환 목표는 `Core_Rule_Spec_v0.2.md` 기준으로 구현한다.

## 중요 전제

- 원작 카드 데이터, 명칭, 일러스트, 스토리, 고유 리소스는 절대 포함하지 않는다.
- 창각의 아테리얼은 보드 배치, 리더, 코스트, 지배력의 구조적 감각만 참고한다.
- `Core_Rule_Spec_v0.1.md`는 기존 구현 비교 기준으로 보존한다.
- `Core_Rule_Spec_v0.2.md`는 Phase15 구현의 목표 룰 문서다.
- v0.2 전환 중에도 룰 엔진은 UI, DOM, Phaser, 브라우저 전역 객체에 의존하지 않는다.
- 카드 이미지는 표시용이다. 룰 판정은 항상 `CardDefinition`, `CardInstance`, `GameState`의 정규 데이터에서 수행한다.
- `energy`는 별도 카드 사용 비용으로 남길 수 있지만, 보드 배치 가능 여부는 칸별 지배력으로 판단한다.
- 시작 덱 30장, 시작 손패 6장 기준을 유지한다.
- 이번 Phase의 구현은 기존 테스트를 무력화하지 않고, 필요한 경우 v0.1 테스트를 v0.2 의미에 맞게 갱신한다.

## Phase 15 최종 목표

다음 전환을 구현한다.

- 리더를 보드 위 위치를 가진 객체로 모델링
- 게임 시작 시 양측 리더를 시작 위치에 배치
- 리더 주변 칸에 지배력 1 적용
- 카드와 효과가 제공하는 지배력을 칸별로 합산
- 카드 배치 조건을 `card.cost <= slotDominance`로 고정
- 최초 배치에서 코스트 1 이하 카드만 합법화
- 주변 카드 배치 후 더 높은 코스트 카드 전개 허용
- 기본 공격 범위를 인접 칸으로 전환
- 상대 리더가 공격 범위 안에 있으면 리더 직접 공격 허용
- 상대 리더 체력 0 이하 승리 조건을 최우선 종료 조건으로 적용
- AI legal action, UI 하이라이트, replay/hash 결정론을 v0.2 룰과 일치시킴

Phase 15 완료 시점에는 다음이 가능해야 한다.

- 새 게임 생성 직후 양측 리더가 보드 위 시작 위치에 존재한다.
- 리더 주변 칸의 `slotDominance`가 1로 계산된다.
- 시작 직후 코스트 1 카드는 합법적으로 배치된다.
- 시작 직후 코스트 2 카드는 지배력 부족으로 배치 실패한다.
- 카드가 추가 지배력을 만들면 코스트 2 이상 카드 전개가 가능하다.
- 인접한 상대 카드만 기본 공격 대상으로 선택된다.
- 비인접 상대 카드 공격은 검증 단계에서 실패한다.
- 인접한 상대 리더 공격으로 리더 체력이 감소한다.
- 리더 체력이 0 이하가 되면 즉시 게임이 종료된다.
- 같은 seed와 같은 action log는 같은 state hash와 event log hash를 만든다.

## 1. 영향 범위 분석

| 영역 | 영향 | 전환 방향 |
|---|---|---|
| `src/board` | 리더 위치, 칸 인접성, 시작 위치 모델 필요 | 슬롯 좌표에서 리더와 유닛의 점유 상태를 함께 표현하고, 인접 칸 조회 helper를 제공한다. |
| `src/dominance` | 전역 한계 중심 계산에서 칸별 지배력 계산으로 전환 | `calculateSlotDominance`를 정규 계산으로 삼고, 리더/카드/효과의 지배력 제공 범위를 합산한다. |
| `src/game` | 시작 보드, 리더 배치, 시작 덱/손패 정합성 영향 | 게임 생성 시 리더 인스턴스 또는 리더 상태를 보드에 배치하고 30장 덱/6장 손패 기준을 유지한다. |
| `src/battle` | 같은 열 전열 우선 규칙에서 인접 공격으로 변경 | 기본 공격 검증을 인접 칸 기준으로 바꾸고, 대상 타입에 리더를 포함한다. |
| `src/ai` | 합법 행동과 평가 함수가 새 배치/공격 규칙을 따라야 함 | AI가 `slotDominance`, 인접 공격, 리더 킬각을 평가하도록 갱신한다. |
| `src/ui` | 지배력 표시와 공격 하이라이트 변경 | 칸별 지배력 숫자, 리더 위치, 인접 공격 대상만 표시하도록 view model을 갱신한다. |
| `src/replay` | 새 상태 필드가 hash와 replay에 포함됨 | 리더 위치, 리더 체력, 칸별 지배력 결과가 결정론적으로 재현되는지 검증한다. |
| `card-data` | 초반 전개 기준과 코스트 곡선 영향 | 새 카드 종류를 늘리지 않고 기존 카드의 코스트/지배력 값만 필요한 범위에서 조정한다. |
| `tests` | v0.1 전열/후열 가정과 v0.2 인접 전투 가정 충돌 | v0.1 보존 테스트와 v0.2 전환 테스트의 의미를 분리한다. |

## 3. 리더 모델

리더는 플레이어 HP의 다른 이름이 아니라 보드 위 위치를 가진 핵심 객체다.

필수 속성:

```text
leaderId
ownerId
currentHealth
maxHealth
slotId
dominanceValue
attackRange
abilities
```

정책:

- 리더의 기본 `dominanceValue`는 주변 칸에 1을 제공한다.
- 리더는 초기 보드에 자동 배치된다.
- 리더가 보드 위 위치를 잃거나 체력이 0 이하가 되면 즉시 승패 판정을 수행한다.
- MVP에서는 리더를 카드 인스턴스와 분리한 `LeaderState`로 시작할 수 있다.
- 최종 목표는 리더도 보드 위치와 전투 대상성을 가진 정규 상태로 관리하는 것이다.

## 4. 칸별 지배력

v0.2의 배치 조건은 다음 하나로 고정한다.

```text
card.cost <= slotDominance
```

`slotDominance`는 다음 값의 합이다.

```text
slotDominance =
  해당 칸에 영향을 주는 내 리더의 dominanceValue
  + 해당 칸에 영향을 주는 내 카드들의 dominanceValue
  + 카드 효과나 시나리오가 추가한 지배력
```

정책:

- 지배력은 소비하지 않는다.
- 지배력은 전장 위치에서 매번 재계산 가능해야 한다.
- `energy`는 카드 사용 비용으로 남길 수 있지만, 보드 배치 조건을 대체하지 않는다.
- 전역 지배력 한계는 v0.2에서 핵심 배치 조건이 아니며, 필요하면 UI 보조값 또는 v0.1 호환값으로 축소한다.

## 5. 전투 규칙

기본 공격 범위는 인접 칸이다.

공격 조건:

```text
1. 공격 가능한 상태여야 한다.
2. 대상이 공격 범위 안에 있어야 한다.
3. 이미 행동한 카드는 다시 공격할 수 없다.
```

정책:

- 기본 공격은 인접한 상대 카드 또는 상대 리더를 대상으로 한다.
- 비인접 대상 공격은 실패한다.
- 기존 같은 열 전열/후열 보호 규칙은 v0.2 전환 중 제거 또는 별도 카드 효과로 축소한다.
- 리더 공격은 전투 규칙을 따르되, 리더 체력 0 이하 승리 조건을 가장 먼저 확인한다.

## 6. 테스트 계획

필수 테스트:

- 리더 초기 배치 테스트
- 리더 주변 지배력 1 계산 테스트
- 코스트 1 카드 최초 배치 성공 테스트
- 코스트 2 카드 최초 배치 실패 테스트
- 주변 카드 배치 후 코스트 2 이상 전개 테스트
- 인접 카드 공격 성공 테스트
- 비인접 카드 공격 실패 테스트
- 리더 공격 및 리더 체력 0 승리 테스트
- AI legal action이 v0.2 배치/공격 규칙만 생성하는지 검증
- UI view model이 칸별 지배력과 인접 대상 하이라이트를 표시하는지 검증
- replay/hash 결정론 테스트 유지
- 룰 엔진 import boundary 테스트 유지
